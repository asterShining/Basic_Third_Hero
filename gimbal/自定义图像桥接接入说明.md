# gimbal 自定义图像桥接接入说明

## 目标链路

当前 gimbal 板上的正式图像链路固定为：

```text
上位机(Pacific_doorlock_sniper)
-> USB CDC 虚拟串口
-> gimbal custom_image_bridge
-> USART6 / VT03 图传发送端
-> 裁判系统 0x0310
-> 自定义客户端 CustomByteBlock
-> 客户端 H.264 重组与显示
```

这里不承担任何图像解码职责，也不参与键鼠/遥控控制逻辑仲裁。

## 协议约束

- `0x0310` payload 固定为 `300B`
- 发送频率上限固定为 `50Hz`
- 当前桥接语义固定为“连续 `raw H.264 Annex-B` 字节流按 300B 固定块透传”
- 不再解析旧的 JPEG 预览 inner packet，也不保留第二套图像协议

## gimbal 侧实现

- `modules/custom_image_bridge/custom_image_bridge.c`
  - USB CDC 回调只负责收原始字节
  - 任务侧把原始字节流切成 `300B` 固定块
  - 每个周期最多经 `USART6 DMA` 下发一包 `0x0310`
- `application/robot.c`
  - `CustomImageBridgeInit()` 在控制模块初始化链内部独立挂载
- `application/robot_task.h`
  - `StartCUSTOMIMAGEBRIDGETASK()` 运行在 `BelowNormal`
  - 周期固定 `20ms`，与 `50Hz` 协议上限对齐

## 不影响控制逻辑的边界

- 不修改 `RobotCMDTask()`
- 不修改 `VideoLinkKM` 键鼠/VT03 解析
- 不修改云台、发射、遥控控制频率
- 图像桥只走 USB CDC 输入和 USART6 输出两端，不复用控制数据解析器

## 联调时应观察的日志

正常情况下应看到：

- `[img_bridge] 通信正常 ... tx0310_delta:... tx0310_total:...`
- `usb_pkt_total` 和 `tx0310_total` 持续增长
- `pending_drop` 长时间保持 `0` 或非常低
- `uart_tx_error_count` 不持续增长

异常时优先看：

- `[img_bridge] 上位机视频流未接收`
  - 说明 USB CDC 入口没有持续收到上位机数据
- `[img_bridge] 已收视频流 但本周期未转发0310`
  - 说明 USART6 忙、TX 出错，或 packet 队列被压住
- `[freeRTOS] CUSTOM IMAGE BRIDGE Task DELAY!`
  - 说明桥接任务执行时间异常，需优先排查 USB/内存搬运或日志刷屏问题

## 上位机要求

上位机必须满足：

- 输出模式：`serial.transport_mode=raw_h264`
- 串口目标：gimbal 暴露出来的 USB CDC 虚拟串口
- 波特率：`921600 8N1`
- 默认彩色稳流参数：
  - `192x192`
  - `18fps`
  - `112kbps`
  - `force_monochrome=false`

## 客户端要求

客户端 custom 视频源必须固定按以下路径接收：

```text
CustomByteBlock -> H264Reassembler -> ffplay(h264)
```

若客户端重新切回 JPEG 或其它 inner packet 语义，这条链路会直接失效。
